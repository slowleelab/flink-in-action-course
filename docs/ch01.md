# 第1章 · 环境搭建

![难度](https://img.shields.io/badge/难度-⭐-green) ![预计时长](https://img.shields.io/badge/预计时长-1.5小时-blue)

> **本章目标**：一条命令拉起全套实验环境（Flink 集群 + Kafka + MySQL + Redis），导入课程代码工程，并跑通第一个作业。

---

## 1.1 三分钟跑通（最快路径）

如果你只想先看到效果，直接执行：

```bash
# 1. 启动全部组件（Flink / Kafka / MySQL / Redis）
docker compose up -d

# 2. 编译课程代码
cd code && mvn compile

# 3. 终端1：起一个 TCP 数据源
nc -lk 9999

# 4. 终端2：运行第一个 Flink 作业
mvn exec:exec -Dexec.mainClass="com.flinkcourse.ch02.StreamWordCount"
```

在终端1输入 `hello flink hello world`，终端2会立即输出实时词频。**没成功？** 按下面章节逐项排查。

## 1.2 基础环境安装

### JDK 11

```bash
# macOS (Homebrew)
brew install openjdk@11
# 验证
java -version    # 应输出 11.x

# Linux (Ubuntu)
sudo apt install openjdk-11-jdk
```

### Maven 3.8+

```bash
brew install maven      # macOS
mvn -v                  # 验证，注意 Java 版本应为 11
```

!> Maven 显示的 Java 版本不对？检查 `~/.m2` 无关，执行 `export JAVA_HOME=$(/usr/libexec/java_home -v 11)`（macOS）后再试。

### Docker

- **macOS**：安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/) 或 [OrbStack](https://orbstack.dev/)（更省资源，推荐）
- **Windows**：必须使用 WSL2 后端
- **Linux**：安装 Docker Engine + Docker Compose 插件

```bash
docker compose version   # 验证 v2.x
```

## 1.3 一键拉起实验集群

**组件复用原则**：课程只部署 Flink 集群本身，公共组件（Kafka/MySQL/Redis）复用本机已有实例——避免资源浪费与端口冲突，也更贴近真实开发环境（中间件由基础设施团队统一维护）。

| 组件 | 地址 | 说明 | 章节 |
|:---|:---|:---|:---|
| flink-jobmanager | **8081** (Web UI) | docker compose 部署 | 全部 |
| flink-taskmanager-1/2（×2） | — | docker compose 部署（各 4 Slot） | 全部 |
| Kafka | localhost:9092（默认） | 本机已有实例，`KAFKA_BOOTSTRAP` 可覆盖 | 第8、10、11章 |
| MySQL | localhost:3306（默认） | 本机已有实例，`MYSQL_*` 可覆盖 | 第9、10章 |
| Redis | localhost:6379（默认） | 本机已有实例，`REDIS_*` 可覆盖 | 第10、11章 |

```bash
docker compose up -d      # 只启动 Flink 集群
docker compose ps         # 查看状态，全部应为 running
```

> 💡 **连接地址怎么配**：代码统一从 `KafkaUtil` / `MysqlUtil` / `RedisUtil` 读取（`code/src/.../common/util/`），默认值即上表；地址不同用环境变量覆盖，无需改代码：
>
> ```bash
> export KAFKA_BOOTSTRAP=localhost:9094   # 例：Kafka 的对外端口是 9094
> export MYSQL_USER=root MYSQL_PASSWORD=xxx
> ```
>
> 若本机没有这些组件、想全套独立部署，把 `docker-compose.yml` 中注释掉的 mysql/redis/kafka 服务取消注释（注意端口冲突）。

### 拉取超时？（国内网络镜像加速）

如果拉取镜像报 `Client.Timeout exceeded` / `manifest unknown` 连不上 Docker Hub，用镜像加速站前缀拉取后重打标签：

```bash
# 以 DaoCloud 加速站为例（也可换 docker.1ms.run 等其他加速站）
M=docker.m.daocloud.io
docker pull $M/library/flink:1.20.1     && docker tag $M/library/flink:1.20.1 flink:1.20.1
docker pull $M/apache/kafka:3.7.0        && docker tag $M/apache/kafka:3.7.0 apache/kafka:3.7.0
docker pull $M/library/mysql:8.0         && docker tag $M/library/mysql:8.0 mysql:8.0
docker pull $M/library/redis:7-alpine    && docker tag $M/library/redis:7-alpine redis:7-alpine

docker compose up -d      # 镜像已在本地，直接启动
```

> 💡 加速站为第三方服务，可用性随时间变化；若某个失效，换一个前缀重试即可。长期方案可在 Docker Desktop 的 **Settings → Docker Engine** 中配置 `registry-mirrors`。

### 验证 Flink Web UI

浏览器打开 <http://localhost:8081>，能看到 Web UI 即成功：

```mermaid
flowchart LR
    A[Overview 页] --> B[Available Task Slots: 8<br/>2个TM × 4 Slot]
    B --> C[先记住这个页面<br/>第3章会回来研究并行度]
```

### 验证 Kafka（30 秒冒烟测试）

假设你的 Kafka 容器名为 `<kafka容器>`（本文以 `lumio-kafka` 为例，apache/kafka 镜像的脚本在 `/opt/kafka/bin/` 下）：

```bash
# 创建测试 topic（-w 标记变量替换为你的容器名）
K=lumio-kafka
docker exec $K /opt/kafka/bin/kafka-topics.sh --create --topic test \
  --partitions 1 --replication-factor 1 --bootstrap-server localhost:9092

# 终端1：消费者
docker exec -it $K /opt/kafka/bin/kafka-console-consumer.sh \
  --topic test --from-beginning --bootstrap-server localhost:9092

# 终端2：生产者，输入几条消息，终端1应实时显示
docker exec -it $K /opt/kafka/bin/kafka-console-producer.sh \
  --topic test --bootstrap-server localhost:9092
```

### 验证 MySQL

```bash
mysql -uroot -p < docker/mysql/init/01_init.sql   # 在本机 MySQL 初始化课程库表与数据
mysql -uroot -p flink_course                       # 验证
```

初始化脚本执行后验证：

```sql
SELECT COUNT(*) FROM orders;   -- 应返回 7
SHOW TABLES;                   -- orders / dws_gmv / risk_alert / dim_city
```

**CDC 前置检查**（第9章需要读 binlog，MySQL 8.0+ 一般默认满足）：

```sql
SHOW VARIABLES WHERE Variable_name IN ('log_bin','binlog_format','server_id');
-- 期望：log_bin=ON, binlog_format=ROW, server_id≠0
```

> 💡 **MySQL 版本兼容**：课程使用 `flink-connector-mysql-cdc 3.6.0-1.20`，支持 MySQL 8.0 ~ 9.x。
> 注意老版本 CDC（≤3.3）读位点用的 `SHOW MASTER STATUS` 在 MySQL 8.4+ 已被移除，会报 SQL 语法错误——这是 CDC 版本与 MySQL 版本不匹配的经典坑。

## 1.4 导入课程代码工程

```bash
cd code
mvn compile      # 首次会下载依赖，3~10 分钟
```

用 IntelliJ IDEA：`File → Open` 选择 `code/pom.xml` → `Open as Project`。

工程结构一览：

```
code/src/main/java/com/flinkcourse/
├── common/                  # 公共 POJO 与工具
│   ├── model/               # Order / UserAction / TransferEvent / DeviceMetric
│   └── util/                # JsonUtil / KafkaUtil / MysqlUtil / RedisUtil（连接配置外置）
├── ch02/                    # 每章一个包，类可独立运行
├── ch03/ ~ ch13/
```

**依赖版本**（无需记忆，了解即可）：

```xml
<!-- 父 pom.xml 关键依赖 -->
<flink.version>1.20.1</flink.version>
<kafka.connector.version>3.3.0-1.20</kafka.connector.version>
<jdbc.connector.version>3.3.0-1.20</jdbc.connector.version>
<mysql.cdc.version>3.6.0-1.20</mysql.cdc.version>
```

> Flink 1.x 系列各版本 API 高度一致，未来升 1.19/1.21 通常只改版本号即可。

## 1.5 跑通第一个作业（精讲）

### 步骤

```bash
# 终端1：TCP 模拟数据源（-l 监听 -k 保持）
nc -lk 9999

# 终端2：
cd code
mvn exec:exec -Dexec.mainClass="com.flinkcourse.ch02.StreamWordCount"
```

在终端1依次输入：

```
hello flink
hello world hello flink
```

终端2输出（数字会随输入累积增长）：

```
3> hello, 3
4> flink, 2
2> world, 1
```

**看懂输出**：`3>` 表示该数据由**并行子任务 3** 输出——这就是并行计算，第3章详解。

### 常见启动失败排查

| 现象 | 原因 | 解决 |
|:---|:---|:---|
| `Connection refused` | nc 没启动 / 端口被占 | 先起 nc；`lsof -i:9999` 查占用 |
| 控制台无输出 | 输入了空行 | 必须输入非空文本并回车 |
| `ClassNotFoundException` | 没先 `mvn compile` | 执行编译后再 run |
| 依赖下载缓慢 | Maven 中央仓库网络问题 | 配置阿里云镜像（见下方） |

?> **提示**：配置阿里云 Maven 镜像可大幅加速依赖下载 —— 在 `~/.m2/settings.xml` 的 `<mirrors>` 中添加 `https://maven.aliyun.com/repository/public`。

<details>
<summary>📖 点开查看阿里云镜像完整配置</summary>

```xml
<mirrors>
  <mirror>
    <id>aliyunmaven</id>
    <mirrorOf>*</mirrorOf>
    <name>阿里云公共仓库</name>
    <url>https://maven.aliyun.com/repository/public</url>
  </mirror>
</mirrors>
```

</details>

## 1.6 关停与重置环境

```bash
docker compose stop          # 临时停止（数据保留）
docker compose up -d         # 再次启动
docker compose down          # 删除容器（数据卷保留）
docker compose down -v       # 连数据一起清空（彻底重来）
```

!> MySQL 初始化脚本**只在首次创建数据卷时执行**。想让 `orders` 表回到初始状态，用 `docker compose down -v` 彻底重置。

## 本章小结

- `docker compose up -d` 一键拉起 Flink(8081)/Kafka(9092)/MySQL(3306)/Redis(6379)；
- 课程代码是单一 Maven 工程，按 `chXX` 包组织，每章示例独立可运行；
- 跑通三要素：**编译 → 数据源(nc) → main 类**；
- 排查问题的第一现场：Web UI、`docker compose logs`、`nc` 数据源。

## ✍️ 动手练习

1. 打开 Flink Web UI，截图记录 **Task Slots 总数**，并思考"2 个 TaskManager × 4 Slot = 8"意味着什么；
2. 用 `kafka-console-producer/consumer` 完成一次自问自答的收发；
3. （可选）把 `docker-compose.yml` 中 taskmanager 的 `scale: 2` 改为 `3`，`docker compose up -d` 观察变化。
